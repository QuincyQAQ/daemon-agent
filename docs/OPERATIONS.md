# 权限、运维与排障

## 权限语义

| 行为 | Act | Plan |
| --- | --- | --- |
| 工作区文件列表/读取/搜索 | 允许 | 允许 |
| 文件创建/编辑 | 每次批准 | 拒绝 |
| 任意 Shell | 每次批准 | 拒绝 |
| MCP 进程启动/工具调用 | 每次批准 | 拒绝 |
| 写入 Memory | 每次批准 | 拒绝 |
| Skills 检索和 inline/fork | 允许，子任务继续受权限控制 | 允许，子任务保持 Plan |
| 在线 Skills 反馈沉淀 | 默认启用，可关闭 | 关闭 |
| 保存会话/审计/检索使用计数 | 允许 | 允许 |

工作区外路径、解析后越界的符号链接、`.env`（模板除外）、`.git`、`.ssh`、`.aws`、`.codex`、`.agents`、私钥后缀及当前状态目录禁止普通文件工具访问。每次文件编辑要求当前全文哈希；精确替换必须唯一匹配。文件写入使用原子替换并保留原文件权限位。

这些是应用层约束。用户批准的 Shell/MCP 进程可以使用当前 OS 用户的权限，路径过滤并不包围任意命令。Shell 去除模型 API key 等继承环境变量，但仍可以读取用户有权限访问的磁盘。运行不可信项目应使用专用容器/用户，不依赖命令黑名单。

源文件路径存在被本地其他进程并发替换的竞态；应用没有实现内核级目录句柄锁或完整的恶意文件系统隔离。不要将该 CLI 作为多租户服务部署。

## 数据管理

- `.bear/` 包含会话、工具输出和学习来源，按敏感项目数据处理。
- 工具审计默认只记录工具名、成功与耗时，不记录完整参数；会话仍会保存工具参数和结果。
- `doctor` 只显示 key 是否存在，不显示其值。Shell/MCP 不默认继承模型 key。
- 备份应在进程停止后复制整个 `.bear/`，或使用 SQLite backup API 做在线快照；不要只复制活跃 WAL 数据库主文件。
- 需要换工作区时创建新会话；恢复检查工作区绝对路径，避免误操作其他项目。
- SDK 常见网络/认证异常仅展示异常类型，不展示可能包含请求材料的详细消息。

## 常见问题

### `Python 3.10+ is required`

使用 `./bear.sh`，或设置 `BEAR_PYTHON=/usr/bin/python3.10`。不要在默认 Python 3.8 环境直接运行包。

### `No module named pip` / `ensurepip is not available`

离线核心不依赖 pip，可以直接运行。需要 SDK 时，使用已带 pip 的 Python 环境，或由系统管理员安装 `python3.10-venv` / `python3-pip` 后创建 `.venv`。本项目不会自动修改系统 Python 或安装 apt 软件包。

### 模型端点返回 400 / 401 / 403

确认 `BEAR_PROVIDER`、`BEAR_MODEL`、对应 API key 与 base URL。OpenAI 兼容服务必须支持 Chat Completions 的 `tools`、`tool_calls` 和 `tool` 消息；仅文本补全兼容并不足够。Anthropic 端点需支持 Messages 工具协议。`doctor` 不发网络请求，因此不能证明凭据有效。

### 非交互任务写入被拒绝

这是默认权限策略。使用终端交互执行并审阅具体操作。自定义嵌入式场景可以给 `Agent(..., approve=callback)` 注入针对明确工具/参数的审批器；调用方承担授权范围管理。离线 `demo` 只批准固定演示文件路径。

### 模型请求超时

`model_wait` 表示仍在等待 API；超时错误本身不能证明密钥无效。学校入口不进行 SDK 隐式重试，以免一次等待被延长为多次。模型请求中断时会保存任务、执行模式、是否正在最后总结，以及此前已完成的工具结果。

在当前 REPL 输入 `/retry`，或退出后使用 `./campus.sh run --resume SESSION_ID --retry`。该操作不追加重复用户任务，也不重新执行已经完成的工具；最后总结失败后重试仍不开放工具。旧版没有超时标记、但末尾为待处理 user/tool 消息的会话会按只总结方式恢复。没有待恢复请求时会提示输入新任务。

### `Stale edit`

文件自读取后已变化，重新调用 `read_file` 并检查内容，再使用新哈希。不要通过 shell 绕过拒绝。

### 会话提示工具结果未知

恢复发生在工具执行与结果保存之间，副作用可能已发生。先读取文件或检查外部服务状态，再决定下一步。程序不会自动重发有副作用的操作。

### 明明读过文件，恢复后却说没读过

旧版上下文压缩失败时只保留最后几个工具结果的片段，可能遗漏 README 等较早依据。新版会从同一会话的本地归档自动重建 `tool_evidence`，并独立保留历史读取记录与限长摘录。退出旧进程后使用原会话 ID 恢复即可；不要删除 `.bear/sessions/archives/`。若归档已丢失或原读取本身被截断，仍需重新读取才能补充缺失内容。

### Skills 评测拒绝空数据

自动 replay 仅保留来源，不会凭模型生成“标准答案”。准备 `query` 和非空字符串数组 `expected_terms` 后显式导入。关键词分数不证明真实任务成功；需要单独开展 end-to-end 任务评测。

### MCP 启动失败 / 超时

先在终端执行配置的 argv；确认工作目录和解释器。stdout 必须仅输出逐行 JSON-RPC；日志写 stderr。当前客户端为避免 stderr 管道堵塞将 stderr 丢弃，调试时应单独运行服务。协议版本仅接受 2025-06-18 或 2024-11-05。

### Docker socket permission denied

这是本机 Docker 访问权限问题，不是镜像构建结果。由管理员按本机策略授权 Docker，或在已有 Docker 权限的环境运行 README 的命令。不要把 Docker socket 挂入 Agent 容器。

## 验证层次

1. 单元/集成测试：真实临时文件、Shell 子进程、MCP 示例服务；模型使用受控 stub。
2. 离线演示：实际工具执行和数据落盘，策略由固定脚本驱动。
3. 真实模型 smoke test：需要用户提供模型配置和凭据，检查工具调用及长任务行为。
4. Docker runtime test：需要可用 Docker daemon，验证构建、权限、挂载与资源限制。
5. 质量/安全评测：独立数据集、多个任务、真实 provider、人工检查和隔离环境。

不能用第 1/2 层的通过替代后续层级。各项验证入口见[功能与验收入口](REQUIREMENTS.md)。
